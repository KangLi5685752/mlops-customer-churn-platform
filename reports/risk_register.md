# Risk Register

This risk register documents residual risks for the local MLOps Customer Churn Prediction & Drift Monitoring Platform. It does not claim that risks are fully eliminated.

| Risk ID | Risk | Category | Likelihood | Impact | Mitigation | Residual Risk | Evidence / Project Control |
| --- | --- | --- | --- | --- | --- | --- | --- |
| R1 | False positives causing unnecessary retention action | Model performance / business process | Medium | Medium | Treat predictions as decision support, review precision, avoid automatic customer treatment and document threshold limitations. | False positives remain possible because precision is moderate. | Model card, evaluation metrics, human review recommendation |
| R2 | False negatives missing likely churners | Model performance | Medium | Medium | Review recall, confusion matrix and threshold tradeoffs before any real use. | False negatives remain possible because recall is moderate. | Model card, evaluation summary, training metrics |
| R3 | Overreliance on churn probability as an automatic decision | Human oversight / governance | Medium | High | State intended use clearly and require human review for customer treatment decisions. | Users may still overinterpret model output if context is lost. | Model card, README limitations, risk register |
| R4 | Public dataset may not represent real customer populations | Data validity | High | High | Avoid production claims, document dataset source and require validation on relevant data before real use. | Generalisation risk remains high for real organisations. | README dataset notes, model card limitations |
| R5 | Simulated drift may not reflect real production drift | Monitoring limitation | High | Medium | Label drift detection as simulated and use it only for local portfolio demonstration. | Real drift patterns may differ substantially. | Drift report, dashboard limitations, model card |
| R6 | Prediction logs may become privacy-sensitive if expanded to real data | Privacy / data governance | Medium | High | Avoid identifiers in current logs and require privacy review before using real customer data. | Privacy risk remains if logging scope expands. | Prediction logger excludes `customerID`, README limitations |
| R7 | Risk label thresholds are not validated business policy | Decision policy | Medium | Medium | Present thresholds as local demonstration rules and recommend threshold analysis before real use. | Thresholds may not match business costs or fairness constraints. | Model card inputs/outputs, decision log |
| R8 | Model performance may change under new data distributions | Data drift / model degradation | Medium | High | Use prediction logging and simulated drift checks as local monitoring evidence; require real monitoring for deployment. | Model degradation risk remains without real production validation. | Prediction logs, simulated drift report, dashboard |
| R9 | Containerised local prototype may be mistaken for production deployment | Communication / deployment risk | Medium | Medium | Document Docker usage as local API containerisation only. | Readers may still overstate deployment maturity. | README Docker section, project evidence summary |
| R10 | Dashboard may create false confidence in monitoring maturity | Monitoring / stakeholder communication | Medium | Medium | Label dashboard as local prototype and include limitations on simulated data and thresholds. | Dashboard may still be mistaken for production observability. | Dashboard limitations, README dashboard notes, model card |
| R11 | Tests may not cover all real-world failure modes | Engineering quality | Medium | Medium | Use pytest and GitHub Actions for core behaviour, while documenting that tests use synthetic fixtures where appropriate. | Untested integration and production edge cases remain. | Tests, CI workflow, README tests section |
| R12 | MLflow local tracking may be mistaken for production governance | Model governance | Medium | Medium | Document MLflow as local file-based tracking and avoid model registry or production compliance claims. | Experiment tracking is not a full governance workflow. | MLflow run summary, README MLflow section, model card limitations |
